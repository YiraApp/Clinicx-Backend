# M2 test case matrix

Every case in NHA's M2 workbook, in the order the sheet groups them, with its marking, its Expected Result and the APIs the sheet lists for it. The sheet merges one APIs cell across the cases of a group, so a case lists every API of its group, and may call only some of them. Before building, read it and build every journey that a case mandatory for your entity type needs. Build each mandatory case's Expected Result into the screen, not only its calls. The test run uses it to know what each case exercises.

Marking is for a government and a private entity, as `abdm_report.py plan` reads the workbook. Mandatory cases come first in each group. 13 cases; 13 mandatory for at least one entity type.

An operation in another module's specification is named with that module. An unresolved path is one the sheet names that no operation in the specifications matches, with the reason: work out the call from the Expected Result and the specification.

- Journeys the mandatory cases need for a government entity: `m2-abdm-hip-initiated-linking-hip`, `m2-abdm-link-token-hip`, `m2-abdm-user-initiated-linking-hip`, `m2-consent-management-data-flow-hip`.
- Journeys the mandatory cases need for a private entity: `m2-abdm-hip-initiated-linking-hip`, `m2-abdm-link-token-hip`, `m2-abdm-user-initiated-linking-hip`, `m2-consent-management-data-flow-hip`.
